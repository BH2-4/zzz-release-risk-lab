<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fixture/model provider -> `mapTheories` | Provider metadata and structured output are untrusted until closed validation succeeds. |
| persisted run -> `validateTheoryAgentRun` | Checked JSON may be stale or tampered and must not inherit authority from its filename. |
| approved mapping -> `finalizeTheorySystem` | Human review and provenance must be bound before content identity is calculated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-PROV-S | Spoofing | `validateTheoryProvenance` | high | mitigate | Enforce the three closed modes and derive `realModelUsed` only from valid mode-specific fields. |
| T-01-PROV-T | Tampering | run/System validators | high | mitigate | Revalidate semantic provenance and digest/lineage consistency after persistence and finalization. |
| T-01-PROV-R | Repudiation | review lineage | medium | mitigate | Retain reviewer/timestamp/target digest and make the approved System match the run review exactly. |
| T-01-PROV-I | Information Disclosure | validator errors | low | accept | The domain validator reports field names and contract violations only; it does not include provider payload contents. |
| T-01-PROV-D | Denial of Service | invalid provider object | medium | mitigate | Reject malformed/unknown modes before lifecycle persistence so invalid input cannot create a resumable run. |

</threat_model>
