# ZZZ Release Risk Lab

## What This Is

An evidence-bounded AI application for ZZZ global publishing operators. It compiles public multilingual material into a reproducible 42-day social pressure test, compares response strategies, visualizes mechanism-level evolution, and can commit a compact run record to Injective testnet.

## Core Value

An operator can trace every simulated divergence back to reviewed public evidence or an explicit synthetic assumption, never to an unexplained probability claim.

## Business Context

- **Customer**: ZZZ global publishing and communications reviewers evaluating the competition demo.
- **Revenue model**: Competition MVP; no monetization or token speculation.
- **Success metric**: A reviewer can complete and understand one fixed-case evidence-to-strategy-to-audit demo on the competition macOS machine in 3-5 minutes.
- **Strategy notes**: `docs/competition-mac-mvp-outline.md` is the active competition route; `docs/mvp-v1-spec.md` retains the broader product target and post-competition backlog.

## Requirements

### Validated

- ✓ Deterministic 125-representative, 42-day baseline and paired sensitivity artifacts exist with explicit non-probability boundaries.
- ✓ A standalone 3D observer replays verified artifacts on desktop and mobile.
- ✓ Public evidence ledger, 11-theory catalog, Evidence Review, and human-gated Theory System primitives exist.
- ✓ Injective transaction encoding, runtime bytecode verification, and mocked wallet flows exist without private-key handling.

### Active

- [ ] Harden the Theory Agent CLI and regenerate authoritative content-addressed output.
- [ ] Complete one fixed-case, source-bound model compilation with attributable provenance.
- [ ] Reuse the existing deterministic 125-representative, 42-day trace and 3D observer in one Mac demo path.
- [ ] Complete an explicitly confirmed Injective testnet commitment and public audit record.
- [ ] Package and verify the final 3-5 minute macOS field demo and offline fallback through a PR-first release gate.

### Out of Scope

- Predicting real players, regions, countries, or crisis probabilities - the population and outputs are synthetic scenario instruments.
- Private or login-gated community data - only public sources may enter research.
- On-chain social computation or large corpora - Injective stores only compact commitments.
- Mainnet, automatic deployment, private-key access, or unconfirmed wallet transactions - irreversible actions require user control.
- Gambling, prediction markets, or economically valuable token mechanics - testnet evidence is audit infrastructure only.
- Pre-competition cross-platform support, CI matrices, or portability claims - the competition MVP supports the current macOS demo machine.
- Pre-competition hybrid cognition, relationship/Reverse emergence, and runtime-driven 3D channels - existing deterministic simulation and replay are reused instead.

## Context

- The default historical anchor is ZZZ 1.4 perspective fade; the 3.1 Lucy outfit case is a labeled synthetic counterfactual.
- Current Node tests expose six Theory Agent CLI security/provenance regressions. This is the first implementation phase.
- A local TokenPlan setup memo exists, but no credential or real-model artifact is considered validated until the bounded Phase 2 call succeeds.
- The current formula simulation and 3D replay are technical baselines, not the final hybrid Agent product.
- `.planning/codebase/` documents the current implementation and trust boundaries.

## Constraints

- **Research**: Every research conclusion binds to public sources in `research/` and the evidence ledger.
- **Epistemic**: Synthetic groups are never described as player samples; risk indices are never described as probabilities.
- **Quality**: Every phase must pass `npm run build`, `npm test`, and `npm run test:e2e` before completion.
- **Platform**: The competition MVP is supported on the current macOS demo machine; cross-platform verification is post-competition work.
- **AI security**: BYOK keys remain in a trusted Node process; model output is untrusted and closed-contract validated.
- **Chain safety**: No automatic Injective deployment, mainnet switch, private-key read, or unconfirmed transaction.
- **Workflow**: Use full GSD discuss -> plan -> execute -> verify -> review; do not use autonomous `gsd--auto` operation.
- **Delivery**: Work on a feature branch. Push and open a PR only after independent review and all three local Mac gates pass; never push known-red work to `main`. Before it can serve as the PR merge gate, the current Ubuntu workflow must become one macOS target-platform job; non-macOS CI is post-competition.
